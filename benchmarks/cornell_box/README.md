# Cornell Box Benchmark — `cornell-box/1.0` (FROZEN)

The renderer's permanent laboratory. Every renderer change is measured against
the same room; the room never changes to flatter a change.

This directory is the single source of truth for the standard:

```
benchmarks/cornell_box/
    scene.json      # authoritative scene description (all constants)
    geometry/       # the frozen OBJ solids (generated, deterministic)
    reference/      # reference path traces (generated once; NEVER regenerated)
    README.md       # this file: the standard + the two-axis protocol
    BASELINE.md     # the ledger: (similarity, FPS) per milestone
```

Generated by `tools/generate_cornell.py`; pinned by `engine_bench_tests`
(CTest, 100 checks). If either tool or test disagrees with this README, **this
README and the ledger win** — stop and re-derive.

## Geometry revision r2 (M3.3.1)

The first on-hardware render of r1 came back 96.5% black: r1 authored all
five room quads with normals pointing AWAY from the room interior (and three
of them with winding contradicting their own `vn`; the spheres were wound
inward against their outward `vn`). The rasterizer shades one-sided, so the
room shaded to zero; the reference path tracer shades two-sided, which is
why the offline cross-checks never caught it. r2 corrects orientation only:
normals and winding face the room interior, positions/sizes/materials/
camera/lights/exposure are byte-identical to r1, and the reference images
(md5s in BASELINE.md) are unchanged. `generate_cornell.py` now refuses to
write geometry that fails orientation validation, and `bench_tests` pins
normals/winding on every build. No ledger rows existed for r1, so no
re-baselining is required; the first row is measured against r2.

## Reference revision r3 (M4): clean 320-spp measurement target

The M3.3 reference renders (64/80 spp) carried visible Monte-Carlo noise,
which measurably depressed SSIM: comparing the raw render against its own
320-spp convergent answer scores similarity 54.32 — noise alone, no
algorithmic disagreement. Since M4 the **measurement target is the clean
set** `reference/cbox0*_clean.ppm` (320 spp, per-spp sample streams,
byte-exact resumable generation — provenance and md5s in BASELINE.md). The
raw renders stay archived, never regenerated. This is a formal
re-baselining event per the ledger rules — clean, because no ledger rows
existed yet.

## M4: heightfield shadows for the rig

The rasterizer now shadows the point-light rig against a captured
**occluder interval field** (max surface from above + min surface from
below, two one-time ortho R16F captures; the PBR shader marches each
light's receiver→light segment in XZ). Exact for convex occluders — the
entire frozen scene. Penumbra quality is the 16-superposition approximation
(per-pixel emitter integration is the M5 slot). `--no-shadows` restores the
M3.3 direct-only renderer for A/B ledger rows.

## Why the Cornell Box

The box is a closed light-transport system with a tiny number of surfaces:
color bleeding, shadowing, falloff, and Fresnel behavior are impossible to
hide, and the reference solution is computable exactly. It has been the
standard physically-based-rendering test scene since the 1980s.

## The standard

- **Geometry** (meters, Y-up, engine convention — yaw 0 looks −Z):
  interior 5.50 × 5.50 × 5.50, front open (+Z).
  Left wall **red** (0.63, 0.065, 0.05), right wall **green** (0.14, 0.45, 0.091),
  floor / ceiling / back **white** (0.725, 0.71, 0.68) — reflectances from the
  pbrt book's cornell_box scene. Tall block 1.0 × 3.3 × 2.4 m, short block
  1.0 × 1.65 × 2.4 m. Rectangular ceiling emitter 1.30 × 1.05 m at y = 5.49,
  one-sided (emits −Y), Lambertian radiance **L_e = 12** (linear).
- **Camera**: (0, 2.75, 8.35), yaw 0, pitch 0, fovY 39.3° — the classic
  open-front view. **Exposure 1.0, fixed.**
- **Rasterizer lighting**: the engine has no area lights yet, so the emitter
  is approximated by a deterministic 4×4 grid of point lights carrying
  matching flux (`Phi = pi * A * L_e`; per light `I = A * L_e / N` — derived
  and pinned in `bench_tests`). Ambient is **zero**: fake ambient would
  disguise exactly the GI gap this benchmark exists to measure.
- The generated C++ header (`sandbox/src/cornell_scene_gen.h`) mirrors these
  constants; it is a stopgap until the M4 scene/material abstraction loads
  `scene.json` directly.

## The three scenes

| Scene      | Geometry                                | What it measures |
|------------|------------------------------------------|------------------|
| `cornell01`| classic box + two blocks                 | direct lighting, diffuse response, color balance, falloff, tonemap. (Shadowing appears in the reference; the residual gap after M4 quantifies penumbra quality.) |
| `cornell02`| cornell01 + mirror / rough-gold / glossy-dielectric spheres | GGX, Fresnel, roughness, specular environment. The mirror shows the lights and almost nothing else — the reference shows the room. That gap is the probes/IBL milestone. Sphere shadows are cast via their exact column intervals since M4. |
| `cornell03`| cornell01 + white baffle under the emitter | indirect illumination. The baffle blocks the direct view of the light and (since M4) casts a real shadow — rays through its [3.4, 5.4] interval block, rays beneath pass. The reference is bounce-only: the largest remaining gap, target of the GI track. |

## Two-axis protocol

The goal is **not** "render Cornell Box fast". It is:

> *increase visual agreement with a trusted reference while maintaining a high
> frame rate.*

Axis 1 — realism: **Cornell similarity** (0–100, SSIM against the reference).
Axis 2 — cost: **FPS / frame time** under the deterministic benchmark mode.

```bash
# similarity run (frozen protocol: 960x540, 300 frames, vsync off)
./build/bin/sandbox --scene cornell01 --benchmark 300 --width 960 --height 540 \
    --out /tmp/cbox01.ppm --report /tmp/cbox01_report.txt
python3 tools/benchmark_compare.py /tmp/cbox01.ppm \
    benchmarks/cornell_box/reference/cbox01_reference.ppm
# repeat for cornell02 / cornell03

# performance-only runs (no reference needed)
./build/bin/sandbox --scene cornell01 --benchmark 1000 --width 1280 --height 720 --report /tmp/perf720.txt
./build/bin/sandbox --scene cornell01 --benchmark 1000 --width 1920 --height 1080 --report /tmp/perf1080.txt
```

Benchmark mode is deterministic: VSync off, fixed camera/lights/exposure, no
input, warmup frames (first 10%) discarded, then the report:

```
=== benchmark report ===
standard: cornell-box/1.0
scene: cornell01
resolution: 960x540  vsync: off
frames: 300 (warmup 30 discarded)
fps avg: ...
frame ms: avg ...  min ...  p95 ...
cpu ms: avg ...  min ...  p95 ...
gpu ms: avg ...  min ...  p95 ... (timer query)
draw calls: 9  triangles: 74  lights: 16
exposure: 1.00 (fixed)  vram: not reported (no core GL query)
```

GPU frame time uses a GL `TIME_ELAPSED` timer query with one-frame-lag
readback; on drivers that misbehave it self-disables and reports `n/a`.
VRAM has no core GL query and is reported as such (an NVX-extension
telemetry line is a possible future addition).

## The reference images

`reference/*.ppm` are path-traced by `tools/reference_pathtracer.py` with the
**same material model as the engine** (Lambert + Cook-Torrance GGX /
height-correlated Smith / Schlick, same alpha floor) and the **same display
transform** (exposure → ACES → sRGB), plus ground-truth transport: true
area-light sampling (NEE + visibility), full bounces, GGX lobe sampling for
specular selection. The reference therefore isolates *transport* differences
(GI, shadows, area vs. grid light) — not BRDF or tonemap differences.

- Protocol resolution 960×540; cbox01/03 at 64 spp, cbox02 at 80 spp, fixed
  seed. Regenerating them is **forbidden** unless the standard itself changes
  (which requires re-baselining the ledger and is expected to never happen).
- The analytic-primitives vs. OBJ-geometry agreement is verified at generation
  time (`--check-obj`): 100% hit/miss agreement, surface deviation within the
  inscribed-tessellation bound, shading normals identical.

## Rules of the laboratory

1. **Never modify** the geometry, camera, lights, materials, or exposure after
   landing. `bench_tests` enforces the constants; the ledger enforces the rest.
2. Every renderer milestone appends a row to `BASELINE.md` — before/after
   similarity and FPS, plus one line on what moved and why.
3. A change that raises FPS but lowers similarity — or vice versa — is not
   automatically good or bad. The ledger exists to make that trade visible,
   which is the entire research question of this engine.
